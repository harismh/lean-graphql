FINDING STATUS
B1 RESOLVED (named arguments at the framework resolver boundary).
   Reusable library:
   - NamedBindings.checkedArguments takes the record layout from the checked AST coordinate.
     It casts the positional `field.Args` along arguments_encoding_code applied to
     canonical_field_represents, then packs it canonically.
   - namedFieldBinding builds an ordinary FieldBinding from a resolver that reads a named
     ArgumentRecord. named_binding_single states the law.
   - GraphQL.lean exports both.
   Executed boundary (NamedBoundary.lean):
   - `join` is in a CheckedIndexed schema (kernel-checked WellFormedSchema and Represents).
   - The independent target is a BindingsByField whose record is built by coordinate
     (inputRecord), not by the library packer.
   - The application bindings use namedFieldBinding. binding_agreement checks them against the
     target through adaptBindings.
   - execution_meaning: for every adapter that agrees with the target, and from independent
     name-indexed Meaning premises for "left" and "right", the result equals
     specification a b. The proof runs coerceNamed, a Graph `.call` node, interpretGraph and
     answerBinding.
   - graph_executes_named_arguments instantiates it with the arguments supplied in reverse
     order.
   Swap rejection, by type-correct mutations with String × String unchanged, each refuted by a
   positive theorem:
   - swapped_binding_rejected: adapter packing (args.2, args.1) gives ¬ BindingAgreement
     target.
   - swapped_coercion_rejected: lookups swapped in the coercer give ¬ CoercionAgreement.
     CoercionAgreement is stated over the independent named Meaning premises.
   - Both have compile-rejection fixtures.
   - coerceNamed now takes its lookup names from layout[left.index] and layout[right.index].
   This is the boundary S2b's concern was about (FieldBinding, Adapter, agreement), on the
   actual interpreter.
   The status is accurate: the older NamedExample is not the closing evidence, and
   generated positional resolver APIs are not migrated.

WHAT S5 ESTABLISHES
- Independent ValidOperation, InProfile and WithinLimits predicates over decoded P2 ASTs,
  with sound and complete preparation (prepare_complete), and kernel-checked limit
  boundaries.
- Declarative scalar, variable and default semantics, proved in both directions for success
  and for ordered rejection. Absent and null stay distinct. A default applies only on absence,
  and explicit null becomes a field argument error where the spec requires one.
- Every supplied variable map gives one of two outcomes (execution_cases):
  - a specified variable request error with no Machine calls;
  - an execution through the actual S4/S4b core, equal to S0 EvalSpec under the
    independently interpreted key.
  An argument error compiles to the S4 error node and never invokes the failed resolver.
- A reusable named-argument binding builder at the FieldBinding/Adapter boundary, executed on
  the graph interpreter, with same-type swaps rejected by independently anchored agreement.

BOUNDARIES (accurately stated in the status)
- Parser and JSON decoding fidelity, the 32768-character limit and parser fuel: no text
  completeness theorem.
- No HTTP, physical batching or asynchronous backends.
- Optimized fault-contract Sat, effect handlers and declared whole-batch transport failure:
  S6.
- Enums, input objects and lists, recursive inputs, aliases, fragments and directives:
  P3 or later.
- Generated positional bindings are not migrated to namedFieldBinding.
