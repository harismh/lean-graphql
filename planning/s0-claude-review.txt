DEFECTS IN IMPLEMENTED CODE

F1. MEDIUM: fake_label_is_insufficient proves nothing about labels. Checks.lean:48-51
The model has no notion of a label. The theorem pairs an arbitrary hypothesis label = caller.tenant
with copied_tenant_is_insufficient.2, so it restates the forged-record result under a misleading
name. Two documents list it as evidence: s0-status ("ineffective fake labels") and the roadmap's S0
gate (L208). The roadmap's concern is that caller-supplied provenance (an occurrence, index or tag)
must not license a value.
Correction: test the actual label form, Occurrence. Show that a real occurrence licenses only its
own row, for example that a valid occurrence of foreignProject cannot license
ProjectLeaf ... ownedProject .title "private". Or show that an occurrence of an owned row does not
license a value from a different row. If that cannot be stated until AuthTree exists, delete this
theorem and keep the claim on the remaining list.

F2. LOW-MEDIUM: no fixture rejects a real foreign record, and no fixture rejects a wrong parent.
Checks.lean:39-46
copied_tenant_is_insufficient uses a non-member, and wrong_field_rejected uses another field of
the same row. Neither exercises the tenant conjunct of ProjectLeaf.mk (Model.lean:147), nor a value
from a different record. projectLeaf_sound still requires owned, so the rule itself is correct.
My probe confirmed: not ProjectLeaf snapshot caller foreignProject .title "private" is provable,
because the record is a member but not owned.
Correction: add that fixture, plus a wrong-parent fixture using the foreign duplicate's title
"private" under ownedProject. The roadmap names "wrong field/parent".

DESIGN NOTES FOR THE NEXT INCREMENT (not defects yet)

N1. Lookup should return the occurrence. Model.lean:39-44, 146-148
The probe confirmed this: with owned duplicates a and b sharing ID "x", project returns a, yet
ProjectLeaf dup caller b .title "second" is derivable. That is correct for a leaf rule, since b is
owned, but AuthTree's root rule must bind the leaf to lookup's chosen occurrence, as s0-status
says. Make that mechanical: give lookupOwned an occurrence-returning form plus a value lemma, so
the root rule names an Occurrence obtained from lookup, not a row value. This also closes F1
properly.

N2. OwnedProject is value membership. Model.lean:101-105
Duplicate equal rows are indistinguishable, which is harmless for values. Index any rule that
depends on the selected position (root lookup, filtered indices) by Occurrence, not by
OwnedProject.

N3. Field declarations omit list and nullability wrappers. Selection.lean:27-31
EvalSpec and Conforms need [Project!]!, Project and Project! to specify bubbling. Add a result
wrapper to ObjectField, and a nullability marker to LeafField, before writing EvalSpec. S2a must
later prove this hand-written table matches demoAst.

N4. Argument literals are narrow. Selection.lean:28
project(id:) accepts only a string literal; GraphQL ID input also accepts an integer literal.
Either is acceptable for P1, but record it as a profile restriction.

N5. projectTasks does not check the parent. Model.lean:78-79
The probe confirmed that a foreign parent with an owned child ID returns that owned task. Under
AuthTree this is unreachable, because object nodes require an owned parent, and the task itself is
owned. State it as an assumed precondition of the child rule, so the S3 contract records it.

N6. ValidPSelection is not decidable. Selection.lean:41
valid_query is proved by hand. A decision procedure, with soundness against the inductive, will be
needed for S1 lowering and for checking fixtures cheaply. Keep the inductive as the specification.
