This roadmap makes application proofs the acceptance criterion for the next prototype.
The first deliverable is a GraphQL application whose response authorization follows
from proved resolver implementations and a compositional theorem about the executor.
Schema certificates, generated signatures, and passing protocol tests remain useful,
but they do not establish that application guarantee.

plan]. The existing prototype is an implementation baseline. Every theorem and new
API below is a proposed deliverable unless the implementation status explicitly records

== The outcome we must demonstrate

Build a small application with tenants, projects, and tasks. It operates first over
an arbitrary finite, immutable snapshot and a principal. Projects and tasks each
store their own tenant. Projects store ordered task IDs; tasks separately store a
project ID. Relationships may be inconsistent, missing, or cross-tenant; IDs may be
duplicated. The safety theorem must handle these cases without a global isolation
assumption.

[source,graphql]
----
type Query {
  project(id: ID!): Project
  projects: [Project!]!
}
type Project {
  id: ID!
  title: String!
  tasks: [Task!]!
}
type Task {
  id: ID!
  title: String!
  project: Project!
}
----

Specify the pure domain behavior now:

* Lookup filters by the principal's tenant before selecting the first matching ID.
  Membership identifies the exact snapshot record occurrence, not just an ID or a
  record whose tenant field happens to match.
* Root `project` returns the selected owned record; missing and foreign records both
  produce `none`. `projects` lists owned records in snapshot order.
* `Project.tasks` follows that project's stored task IDs, uses owned lookup, and
  omits missing or foreign tasks. Response indices refer to this filtered list.
* `Task.project` uses the task's independently stored project ID. A missing or foreign
  target produces the same closed public error, `Unavailable`, because this field is
  non-null. Ownership of the task does not establish ownership of that target.
* Scalar fields return the specified projection of the exact parent record. The
  public error algebra uses fixed codes and approved request-derived paths; it has
  no arbitrary backend-message `String` payload.

S0 defines a small first-order `PSelection`: field names, literal arguments, and child
selections, without execution-IR features. Define a hand-written inductive
`AuthTree principal snapshot selection tree` over that type, independently of the
resolver implementation and generic contract machinery. Domain-object nodes require
exact snapshot membership and tenant equality; the public query root, containers, and
response envelope have separate structural rules and are not database records.
Root and relationship field rules follow the domain relations above. Each scalar leaf
identifies its field, parent occurrence, and permitted projection. List, null, and
failure rules complete the tree. Ghost evidence is constructed from proved
postconditions; a resolver-supplied provenance label is not evidence.

[source,text]
----
AuthorizedResponse p snap op response :=
  exists tree, AuthTree p snap op tree AND erase tree = response
----

The theorem certifies a valid authorization derivation for the returned values. It
is not a causal audit of every read or branch in the implementation. Implicit flows,
such as choosing a public constant after inspecting foreign data, are outside this
property. Full confidentiality of timing, logs, and all existence observations is
also excluded. The stronger view theorem discussed below addresses modeled output
independence separately.

=== Expected failures and successful behavior

Fix concrete expected results in S0. An owned project can include an owned task whose
separate project reference targets a foreign record. Selecting that task's non-null
`project` produces `Unavailable`; with `Task!` inside `[Task!]!`, it bubbles through
`Project.tasks`. Under root `project(id:)`, that nullable project becomes null; under
root `projects: [Project!]!`, it reaches `data: null`. Keep the original selected error
path and use the filtered list index. A foreign task pointing at an owned project must
still be omitted from `Project.tasks`.

Safety holds for arbitrary snapshots, including duplicate IDs. Functional results and
error-free execution have separate, explicit conditions: unique IDs, existing owned
roots requested by lookup, valid owned targets for required traversed relationships,
successful argument interpretation and no injected faults. The planned pure graph
interpreter terminates structurally and has no execution-fuel premise.

The success obligation is universal over every operation in the declared profile
under those conditions: it conforms to the selection, equals the independent domain
and execution specification, and has no errors. One working demo query is insufficient.
A program that always fails, or handles only a hard-coded query, must fail this gate.

== The proof boundary

The unconditional result is about the concrete pure snapshot program, for every
principal and finite snapshot. The following boundaries must be named explicitly.

[cols="1,2,2",options="header"]
|===
|Boundary |Evidence or assumption |Claim allowed
|Schema and operation ASTs
|Independent validity and meaning relations; checker certificates
|Accepted ASTs denote the certified schema or operation in the declared profile
|Generated bindings
|Correspondence to an independently supplied field-indexed implementation family
|An adapter invokes the designated implementation with the correct conversions
|Pure resolvers and executor
|Concrete contract proofs and compositional preservation
|The modeled application satisfies its stated response properties
|GraphQL text, JSON envelope, and variable decoding
|Initially bounded and tested; every produced value goes through proved validation
|Universal safety for accepted values; exact source-text/JSON fidelity remains separate
|Ordered encoding and UTF-8
|An independent encoding relation and proofs about shipped functions
|The structured result is preserved in the returned bytes
|Authentication
|External `AuthSound`: the returned principal corresponds to the caller
|The kernel theorem holds for whichever principal is supplied; identity binding is external
|Snapshot acquisition
|`SingleSnapshot`: bind one immutable value before execution; external authenticity if it represents a live database
|The response is justified relative to that captured value, not an unmodeled changing database
|Backend
|`BackendRefines`: a supplied certified outcome producer with the required postconditions
|A backend participates only when it can provide that evidence; no global axiom supplies it
|Lean native compiler, runtime, LeanIO, and network
|Explicit trusted execution boundary, including reviewed implementation substitutions
|Returned certified values have their modeled meaning assuming faithful execution and delivery
|===

Neither parsing nor request decoding can construct a certified plan directly. Their
errors can change request meaning, so source fidelity is not claimed yet. Safety can
still hold for every accepted decoded operation and variable value.

The tenant comes from authenticated context, never an arbitrary GraphQL argument.
An external adapter unable to produce the required outcome evidence remains outside
the certified API. Proof-carrying types do not establish database authenticity or
transaction isolation by themselves. Cancellation and nontermination can prevent a
result; they are not an availability theorem.

== S0 Define the property before the machinery

*Build.* Define the finite snapshot, principal, deterministic owned lookup, field
projection relations, closed errors, and `PSelection`. State the independent
`AuthTree`, `Conforms`, and total `EvalSpec` over `PSelection`, before introducing
the IR. Define `ValidPSelection` independently, including field existence, literal
argument types, and legal child selections. `EvalSpec` is total on these valid selections
for arbitrary snapshots, specifying successes, missing targets, and exact null/error
propagation. It takes independent domain field meanings, not resolver implementations.
Keep it free of execution fuel and injected faults. The new structural interpreter
will prove exact agreement for the concrete pure backend; external resource limits
and faults belong to the separate safety theorem. Failures in `EvalSpec` are not unconstrained alternatives.

`AuthTree` permits fixed framework exhaustion/internal failures at any selected field
and argument failures at their field, with prescribed paths and completion. This
supports safety under faults without weakening the independent exactness theorem.
Write every hypothesis explicitly; "admitted" or "well formed" must not hide a policy premise.

*How to prove it.* Build an authorized result witness. Prove rejection of a forged
record with a copied tenant ID, a wrong field/parent projection with distinct fixture
values, and fake provenance labels. Define `erase` separately from authorization rules.
Prove missing and foreign targets give the specified identical outcomes. Record that
implicit flows are allowed by authorization alone.
Use recursion on finite selections and lists to define total evaluation; a recursive
schema does not imply an infinite operation. Keep its equations independent of the
executor and the generic contract judgment.

*Acceptance.* Exhibit cross-tenant edges and duplicate IDs satisfying every hypothesis
of the safety theorem. The functional-success hypotheses are separate and enumerated.
A task's tenant is its own stored field. Public errors, filtered indices, and the
exact null-bubbling examples above are part of the specification. No safety premise
assumes the desired isolation property. Adding an unexplained `Unavailable` failure
must violate `EvalSpec`, even on a snapshot outside the error-free success conditions.

== S1 Define typed plans with an independent meaning

*Build.* Retain finite schema-local identifiers and field-indexed calls. A call carries
its parent model, arguments, and canonical field identity; its answer type depends on
that field. Reserve both call forms now:

[source,text]
----
Call.one field parent args
Answer (one ...) = Outcome (FieldResult field)
Call.batch field scope (inputs : Vector (Parent field × Args field) n)
Answer (batch ...) = Vector (Outcome (FieldResult field)) n
----

The batch precondition supplies the single-call precondition for each input plus
scope compatibility. Its fixed postcondition supplies the corresponding single-call
postcondition at every position. Postconditions alone do not imply equality with
single-call outcomes; exact batch refinement is an additional S4b law. The batch
constructor can remain unused until then, without changing S3/S4 quantification.
Object carriers are models or typed references, not recursively unfolded
host types. `Outcome` parameterizes a closed application error type alongside fixed
framework errors. Successful non-null output can still fail. Preserve omission,
explicit null, and supplied input as distinct values.

Adopt the separation of execution and output planning described by
https://grafast.org/grafast/operation-plan/[Grafast], as architectural inspiration.
This project proves its own Lean definitions; it does not verify Grafast's TypeScript
implementation or adopt its performance claims as premises.

S1a-S1d implementation is complete and reviewed as of 2026-11-05.
See `s1-status.adoc`, `s1-review-resolution.txt`, and `s1-claude-closure.txt` for
proof coverage, validation, review resolution and explicit later-slice limits.

=== S1a Establish the independent target

First discharge the S0 review's consistency obligation for every finite snapshot,
principal, and valid P1 selection:

[source,text]
----
ValidOperation selection
  -> AuthorizedResponse snapshot principal selection
       (EvalSpec (tenantMeanings snapshot principal) selection)
----

Also prove conformance of that reference result. Keep EvalSpec, AuthTree, and Conforms
independent; none may be redefined through the new plan representation. Add the
occurrence lookup converse/none lemmas needed by lowering. Preserve S0's explicit
string-only ID literal restriction. Parameterize reusable response/completion code by
application error before introducing the second contract instance; the tenant model
remains a concrete instantiation. Extend or enforce theorem-audit discovery syntax
before introducing declarations the current scanner cannot discover.

=== S1b Separate four representations

[cols="1,3",options="header"]
|===
|Representation |Responsibilities
|Selection template
|Field identities, argument expressions, guarded occurrences, inherited child guards, and source ordering; variable-parametric
|Resolved selection IR
|Unique response keys, fixed order, per-concrete-type selections, checked arguments or a specified argument error; no runtime guards
|Execution plan
|Typed dependencies and structured dataflow for reads and pure computations; no response-key merging
|Output plan
|Typed references to execution results, response occurrence identity, list reconstruction, field order, nullability boundaries, and error paths
|===

P1 template guards are true. Later instantiation preserves each occurrence's child
guards, enables a field when any contributing occurrence is enabled, and orders fields
by the first enabled occurrence. Collection, guard evaluation, and merging remain
outside execution. Unsupported features remain rejected until their later profile gate.

An operation plan pairs an execution graph with an output plan indexed by that same
graph. Sharing a computation must not merge its response occurrences: each occurrence
retains its own completion boundary and error path. Fetch identity and output identity
are different types, not interchangeable integer indices.

=== S1c Make the graph structurally safe

Use a finite, topologically ordered dependent sequence of nodes. A dependency can
reference only an earlier node with the required output type. This makes missing
references, type mismatches, and cycles unrepresentable. Graph acyclicity establishes
structural traversal termination; it does not establish termination of external IO.

Do not expand lists into a plan node per future record. Provide a restricted structured
`each`/region form: a finite body graph executes over runtime items. Nested regions
have explicit captured dependencies and typed row correspondence. The static region
graph is acyclic even though schemas are recursive and runtime batch sizes vary.
P1 lowering initially emits pure projection, single-field calls, and structured list
traversal. S1 also defines typed gather, pointwise vector map, scatter, and vector-load
forms, so S4b's transformed plan is already representable. Gather spans all parent
rows of one region/wave instance and records each item's parent and position; scatter
uses that provenance to reconstruct the nested rows. Prove their structural denotation
laws in S1d even though P1 lowering does not yet emit the batched arrangement.

Vector-load denotes pointwise single lookup. S4's sequential interpreter implements it
with single calls; S4b supplies a certified batch capability and implementation strategy
using the reserved Call.batch constructor. Deduplication/chunking algorithms,
eligibility, backend refinement, and the transformation belong to S4b. No syntax,
Call/Answer family, or independent semantics is added by the rewrite slice.

Represent batch values with their cardinality, for example `Vector (Outcome A) n`.
An `n`-indexed result rules out length mistakes, but correct key-to-result matching
requires a separate theorem. Flatten/filter/scatter maps must preserve parent
occurrences, duplicates, original order, and output positions after filtering.
Unary request data and per-item data have distinct types or explicit proven broadcasts.

Plans are descriptions parameterized by request context; they do not capture a
principal's records or results for later requests. Cache reuse is not implemented in
S1. Future reuse must check schema/policy/plan-specialization constraints and bind
fresh request data. No same-key or same-step-class shortcut establishes equivalence.

The existing `Machine` has arbitrary continuation functions. It is a suitable target
for a sequential interpreter, not an inspectable representation from which to recover
this graph. In S1-S4b, verified lowering alone constructs application plans from
selections and field bindings. Author-written plan resolvers are a named future
extension, requiring a proof that each supplied field plan denotes its independently
specified field meaning. Do not promise automatic extraction of optimizable plans
from arbitrary Lean functions or IO.

Choose structural termination for the pure interpreter: finite node sequences,
well-founded nesting of finite region bodies, finite runtime input vectors, and total
pure projection functions. There is no unrestricted recursive region call and no fuel
parameter. External limits may still produce certified framework exhaustion failures;
this is a runtime policy, not a precondition of pure denotational equality.

=== S1d Give planning an explicit semantic contract

Define plan denotation against supplied domain field meanings and output reconstruction.
Prove P1 lowering from the independent surface syntax into the resolved selection IR,
and from that IR into the paired operation plan, preserves meaning. These are semantic
functions over the plan language, not yet a proof about the shipped executor.

*How to prove it.* Use induction on selections and structured regions, and the order
of the dependent node sequence. Prove schema lookup and boundary conversion soundness,
then prove each planning constructor preserves denotation. Output references must be
transported with a checked remapping when a later rewrite changes the graph. Prefer
order-preserving typed context embeddings for structural extensions; use a typed
substitution/result-correspondence proof when sharing or replacement is not an embedding. Prove
flatten/reconstruct laws, including empty lists, duplicate keys, omitted targets,
per-item errors, and nested parent positions. Prove composition of one-level gathers
and scatters: the S4b task wave spans project rows and then their task rows, and must
retain both positions. Typing alone is not an order or policy proof.

[source,text]
----
lowerP1 selection = ok selected
  -> ValidPSelection selection AND
       SelectionDenotes meanings selected = EvalSpec meanings selection

plan selected = operationPlan
  -> OutputDenotes operationPlan.output
       (ExecutionDenotes meanings operationPlan.graph)
       = SelectionDenotes meanings selected
----

*Acceptance.* Deliver a narrow P1 plan and output representation, total denotational
semantics, the two lowering proofs, and the universal S0 consistency theorem. Negative
fixtures reject wrong-schema IDs, wrong parent/result types, forward/cyclic references,
wrong batch lengths, and output references from another graph. Semantic counterexamples
reject reordered scatter, wrong-parent reconstruction, and conflation of an omitted
input with null. A finite nested project/task plan must preserve S0's successful and
bubbling results. There is still no optimizer or asynchronous scheduling claim at S1.

Gate implementation in order: S1a consistency; S1b-c representations and negative
fixtures; S1d structural laws and lowering proofs. S2a binding experiments may begin
once the S1b-c call and graph interfaces pass, but S3/S4 cannot close before S1d.
This overlaps interface experiments without treating a partial S1 as complete.

== S2a Exercise the binding shape before generating it

S2a is implemented and reviewed as of 2026-11-05. See
link:s2a-status.adoc[scope and measurements] and
link:s2a-claude-closure.txt[implementation closure and subsequent proof gates].
S2b follows completed S3/S4. Its argument-layout, projection and benchmark entry gates are implemented; see link:s2b-status.adoc[S2b status].

*Build.* Expose the parsed demo schema as a readable `demoAst`. Define a supported-profile
`WellFormedSchema` and `Represents demoAst indexedSchema`. Construct the smallest typed
bindings and adapter equations explicitly, using the shape the generator will later emit.
These are a golden artifact and the application's actual bindings, not a second executor.
The independently anchored BindingsByField interface includes an optional batch
implementation/capability per field, with indexed inputs and pointwise postconditions.
A deduplicating capability also supplies a field-specific key function and its
sufficiency law for the actual deterministic backend: equal keys under the same scope
imply equal single-call outcomes. S2b preserves the key, law, backend binding, and
canonical field identity together. A plain batch capability without a sufficient key
can batch, but cannot enable deduplication. Scope is a runtime request-context token,
not principal records or cached results embedded in a reusable plan.
Generated S2b artifacts preserve this slot and its identity. Absence uses the sequential
fallback; only a separately proved exact-refinement capability enables S4b batching.
A fallback that loops over single backend calls does not satisfy the reduced-call bound.

*How to prove it.* Anchor implementations to canonical field identities obtained from
the checked AST. An independent `BindingsByField` family and field contracts identify,
for example, `Project.title` by that coordinate, not by a generator-provided alias.
Prove that interpreting the adapter for that field invokes that designated implementation
on the correctly translated arguments and outcome. Establish input/output conversion
laws for both successful values and public failures.

*Acceptance.* Swapping two same-typed fields cannot be justified by also swapping a
mapping generated alongside them. The agreement target is supplied independently of
adapter generation. The concrete application proofs refer to the canonical identities.
Try the schema evidence strategy on small, mixed, and existing scalar-only workloads
now; record kernel checking time and memory before committing to a large generator.

== S3 Prove useful resolver behavior

Complete and reviewed on 2026-11-05: link:s3-status.adoc[contracts and bridge evidence]
and link:s3-claude-closure.txt[Claude closure]. Every compiled P1 graph has a
contract certificate, and deterministic certified frames have a proved render bridge.

*Build.* Define a generic result specification with object invariants, call preconditions,
outcome postconditions, and leaf, list, error, and completion rules. Contracts cover
plan nodes and region rows, including pure projections, captures, gather/scatter, and
single/batch calls. Each row value carries the invariant consumed by the output plan;
resolver contracts alone are insufficient once computations form a DAG. Whole-list properties
must be expressible; an elementwise ownership predicate alone cannot express a length
bound. The response conclusion is a parameterized judgment. Instantiate it with tenant
rules, then prove that judgment implies S0's independent `AuthorizedResponse`; do not
redefine `AuthTree` through the framework. The list-bound example follows the same
pattern. S3 defines the obligations for this bridge; S4 discharges them through the
executor. Users supply the required closure laws; arbitrary postconditions do not
automatically survive projection or completion. Merging preservation belongs to
template instantiation, outside the core judgment.

Contracts are optional at the application level. A verified program must cover every
reachable field, including scalar fields and failures. An uncontracted field cannot
silently inherit the program's guarantee.

*How to prove it.* Prove the concrete lookup, listing, child traversal, scalar projection,
and public-failure functions satisfy their independent domain relations. Use lookup and
filtering lemmas and case analysis on every outcome. Lift these through S2a's adapter
agreement interface and package `tenantResolvers_satisfy_contracts`. State S3/S4
theorems for any adapter satisfying that interface, then instantiate them with the
manual equations; generated certificates will later use exactly the same interface.

A GraphQL-valid request does not establish a business precondition. Resolvers must
handle every type-correct input with a specified value or denial. A stronger precondition
requires a proved guard that either supplies its evidence or returns an allowed public
failure before issuing the call. Never assume user-supplied IDs are already owned.

*Acceptance.* The application uses a proved bundle, not an axiom that safe resolvers
exist. Removing an ownership check, projecting the wrong field, or exposing private
failure text breaks the relevant obligation. The spec interface also admits the independent
list-bound instance required in S4, without tenant-specific rules in the framework.

=== Implementation and proof

*Build.* Refactor the actual execution path to interpret S1's execution DAG and output
plan, using typed calls. Start with a sequential graph interpreter and output
reconstruction; prove that this shipped path implements their denotation. P1 uses
statically constructed typed operations. Preserve the current pure
`Machine` design, but prove its algebra and continuations directly; its accumulated
values are inside closures, not an inspectable state record.

*How to prove it.* Define the following schematic predicate by structural recursion:

[source,text]
----
Sat (done value) Q := Q value
Sat (pending call resume) Q :=
  Pre call AND forall answer, Post call answer -> Sat (resume answer) Q
----

Provide `LawfulMonad` for the machine and prove `Sat` rules for bind and list traversal. Prove the
graph interpretation, structured-region traversal, and output completion by induction
on their finite structure, using
`Sat` with the generic result judgment as the conclusion. The pure interpretation theorem
then follows by induction on `Machine`, supplying the concrete resolver postconditions.
There are two proof routes with distinct purposes. For the deterministic pure backend,
interpreter equality with plan denotation, the S1 lowering laws, and S1a consistency
immediately yield authorization and conformance; do not duplicate that proof through Sat.
The generic Sat route proves safety for permitted external faults and resource-limit
failures and supplies S6's certified driver. It requires a separate bridge from row/node
invariants and output completion to the hand-written AuthTree witness and erasure.
A generic framework theorem alone is not that bridge.

Establish scalar, object, list, null, and failure cases for both the application relation
and independent `Conforms`/`EvalSpec`. Cover all four list/nullability combinations,
nullable sibling preservation, and the error path and multiplicity through bubbling.
A field error remains an error outcome even for non-null output; it cannot become an
ordinary successful null. Paths use positions in the filtered resolver result.
Include the specified argument-error branch now and prove it performs no resolver
call. This branch must not require reopening the execution theorem when S5 arrives.

The sequential pure interpreter terminates by the S1 structural measure and has no
fuel parameter. Prove equality with total EvalSpec on all arbitrary snapshots,
including legitimate domain failures. Separately prove error-free success under S0's

== S4b Prove one batching transformation

S4b is complete and independently reviewed: link:s4b-status.adoc[scoped transformation, proofs and cost model]
and link:s4b-claude-closure.txt[Claude closure]. S5 implementation and review status are recorded below.

*Build.* After the unoptimized application theorem and generated bindings work, add

positions. Keep the unoptimized plan as a reference path.

This target is deliberately an existing selected field-call node. It does not require
inspecting an opaque `Project.tasks` resolver or extracting its internal task-ID lookups.
The earlier `Project.tasks` loads remain unoptimized and outside this stage's reduced
call count. Exposing internal loader plans requires the later certified plan-resolver API.

Scope each batch to the same authenticated principal/policy, immutable snapshot,
backend, and compatible arguments. The first rewrite covers deterministic read-only
snapshot lookups. No mutation, arbitrary effect, cross-request result cache, or
unproved SQL fusion participates. Operation-plan optimization must update the paired
output plan and preserve every response occurrence, not just graph node values.

*How to prove it.* Define an eligibility predicate from independently checkable plan
structure and contracts, including the presence of the selected batch capability and
its key-sufficiency law for the actual backend. The same key function determines
representatives, scatter correspondence, and U in the call-count theorem. For the pure backend, prove that two owned tasks with the same scoped project ID have
the same required-project lookup outcome. This field-specific key sufficiency theorem
justifies deduplication even when parent task records differ. Then prove batch lookup agrees
with single lookup at every input position, including missing keys and the exact first
owned occurrence when IDs are duplicated. Prove deduplicate/scatter reconstructs the
original sequence and preserves all per-occurrence paths and error multiplicities.
A shared failed computation must still produce the errors required at its separate
response positions. Use those laws to prove equality of complete structured responses,
including ordered fields, list positions, data, public errors, and null propagation.

State response equivalence over a deterministic backend function whose batch results
equal its pointwise single-call results and whose capability key is sufficient for
those same single-call outcomes, with the pure snapshot backend as a concrete
instance. External IO adapters inherit certificate-level safety through S6's typed
postconditions, not an equality between opaque IO computations. A whole-batch transport
failure is not equivalent to selected per-key
failures merely because both are permitted by an authorization predicate. Exactness
requires the deterministic refinement law; generic fault safety remains separate.
Preserve effect order for excluded operations by leaving their plans unchanged.

Instrument the actual Machine program emitted by the batch strategy, counting its
primitive-call constructors for a given answer sequence. A region/wave instance here
spans all filtered task rows available across the project parents together; U counts
distinct (scope, projectId) keys over those rows, not separately for each project. For capacity B > 0, prove
at most ceil(U / B) total primitive calls issued for that transformed load, counting
both single and batch calls. Require the certified batch capability to be present;
the single-call fallback is outside this reduced-count theorem. This is a theorem about the counted Machine interpretation,
not IO. Interpreting it as physical backend requests assumes one request per primitive
and no retries. For multiple regions or dependency waves, sum their individual bounds;
do not claim a single global bound. Record a concrete workload where the proved bound
is strictly smaller than the reference path's count. Hidden backend work and wall-clock
latency are outside this cost model.

*Acceptance.* The actual transformed path has a response-equivalence theorem and
inherits the application authorization theorem. Kernel-checked examples include repeated
keys across parents, two owned records sharing an ID, cross-tenant targets, empty lists,
chunk boundaries, per-item failure, and nested filtered error paths. Deliberately
wrong scatter maps and unsafe scope combinations must fail the intended obligations.
A backend-call benchmark corroborates the proved count without standing in for it.
Finish this one optimization before pursuing a general optimizer or broader features.

== Evidence required to close every slice

. State the property, domain, assumptions, and excluded observations before implementing it.
. Identify the executable definition covered by each theorem and its caller in the application.
. Build the proof and inspect its axioms and relevant dependencies. Reject placeholders,
  unsound axioms, unchecked casts, and unreviewed implementation substitutions.
. Keep independent examples and counterexamples, plus nontrivial successful executions.
. Check that schema/resolver changes invalidate the appropriate artifacts and evidence.
. Label remaining guarantees as type-enforced, proved, tested, or assumed.

Review the theorem's meaning as well as its kernel acceptance. An axiom listing alone

https://lean-lang.org/doc/reference/latest/ValidatingProofs/[proof validation guidance]
