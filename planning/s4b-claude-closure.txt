WHAT S4b ESTABLISHES
- One certified batching transformation on the actual executable path: Batching.execute for
  { projects { tasks { project { … } } } } with a present exact and keyed Task.project
  capability. Every other operation falls back to the unchanged Runtime.execute.
- Equality of the whole structured response with Runtime.run, for every deterministic adapter,
  through the unchanged compiled child graph and output plan. Authorization and conformance
  are inherited for every agreeing adapter.
- Deduplication, representatives and U come from one request-scoped key whose sufficiency law
  belongs to the same single backend. A batch cannot mix requests, and there is no cache.
  Shared failures still appear at every original response occurrence.
- An exact, answer-independent count of ceil(U/B) for the selected stage, in nonempty chunks of
  at most B, and a whole-program breakdown with
  optimized + |positions| = reference + ceil(U/B) under the exact driver.
- The counts are Machine primitives. Neither physical requests nor latency is claimed, and the
  pure capability is still a pointwise loop.
