WHAT HOLDS IN S3
- Generic calculus (Specifications.lean). There is a GraphProof or NodeProof constructor for each
  of literal, map, pair, call, gather, scatter, fromLists, vectorLoad, each and mapRows.
  - Calls and every vectorLoad index must establish `pre` from the current precondition.
  - Every map, pair or literal needs an explicit closure proof, so an arbitrary map inherits
    nothing (the ContractUnprovedMap fixture).
  - Region bodies are proved against the actual row and captured values (args = (row,
    captures.read values)).
  - `each` relates inputs and outputs by RelatedLists, which preserves order and cardinality.
  - mapRows relates them through RowIndex coordinates.
  graph_proof_sound is proved by mutual induction over all constructors with BackendSatisfies,
  and has no gaps.
- Whole-list properties. Postconditions are arbitrary predicates on complete values.
  result_collect_bound together with elementwise_is_insufficient shows that a cardinality bound is
  expressible and does not follow from elementwise validity.
- Tenant contracts:
  - Expected is independent of the resolver record. It is written over Model-level domain
    functions.
  - Root preconditions are True, so user IDs are unrestricted; root_project accepts any key.
  - Child preconditions require an owned parent, and foreign_parent_rejected shows that a record's
    type does not supply this.
  - Postconditions require exact domain behavior and ownership or the allowed public failure.
    expected_owned proves the ownership half from the domain lemmas, for every field.
- Response judgment. Judgment and ResponseJudgment are free of tenant facts, and
  judgment_sound and response_judgment_sound are correct. ResponseContract.rules_preserve
  implies the unchanged AuthTree, AuthField and AuthItems, and response_authorized gives
  AuthorizedResponse. The framework rule admits declared framework failures, and
  response_rule_example uses it non-vacuously (exhausted on `projects`).
- Mutation evidence:
  - removed_ownership_guard_rejected uses the ownership conjunct.
  - swapped_scalar_rejected and unexpected_error_rejected are both present.
  - The private-text fixture fails because ApplicationError has no string slot.
- The scope statement is accurate: there are no executor, Sat, I/O, batching or cost claims.

S3 BLOCKER

B1. No compiled tenant plan is ever certified, so the row invariants are never shown to feed the
next call.
(Compile.lean compileFor; Specifications.lean; Contracts.lean. Grep: GraphProof and NodeProof
occur outside Specifications.lean only in BoundedExample.)
The roadmap's S3 build requires this (L447-452): "Contracts cover plan nodes and region rows ...
Each row value carries the invariant consumed by the output plan; resolver contracts alone are
insufficient once computations form a DAG." The status claims "Every reachable call requires its
business precondition" and "Child calls require an owned parent; this is a program obligation".
The calculus does let such a requirement be stated. But nothing shows that the program the
application actually runs meets it.
- tenantResolvers_satisfy_contracts concerns the backend only.
- The only GraphProof is BoundedExample.plan_certificate: one call node whose precondition is True,
  with no rows, regions, captures or branchRows.
The ownership chain is therefore unproved. That chain is: Projects or Project.tasks output satisfies
OutputInvariant; branchRows preserves it; the `each` body precondition holds; the child call's
`pre` (an OwnedProject or OwnedTask parent) holds.
The roadmap also calls the precondition a program obligation (L472-475): "A stronger precondition
requires a proved guard". Without a certificate, that obligation is never discharged anywhere.

Fix:
1. Prove a certificate for every compiled plan, generic over the resolved selection, by
   induction on IR.Resolved following compile_for_correct:
     theorem compiled_certificate (resolved : IR.Resolved object selection) :
       GraphProof Contract.tenant (compileFor Binding.carriers Binding.Request resolved).graph
         (fun v => Contract.ObjectInvariant v.2.1 (objectId object) v.1)
         (FrameInvariant resolved)
   - FrameInvariant records, for each OutputFor reference, that the outcome read satisfies `post`
     (and so Expected and AllowedOutcome).
   - It records that each region's frames are RelatedLists to branchRows of that outcome, with
     the child FrameInvariant holding at each row.
   The key lemma: AllowedOutcome for a branch output implies ObjectInvariant for every element of
   branchRows. The argument-error branch of callNode, a map that ignores the backend, closes
   trivially. The root carrier (Unit) has the invariant True.
2. Compose it with graph_proof_sound and tenantResolvers_satisfy_contracts:
   for every agreeing adapter, Request, and checked operation, FrameInvariant holds of the
   denoted frame. That gives exactly the "every call issued had its precondition" property, with
   the token tied to the request.
3. Add one negative fixture showing the certificate is not vacuous. Take a hand-built graph that
   calls Project.title on a literal foreign Project record, or that bypasses branchRows and
   iterates over an unfiltered literal list. Prove that its `each` or call precondition fails.
   For instance, prove ¬ NodeProof for that node under P = the root invariant, by refuting `ready`
   at a concrete value.
This is pure, plan-level work. It needs no executor, so it belongs in S3, not S4.

HIGH: S4 entry condition

H1. OutputBridge restates the final theorem, and the local rules mirror AuthTree.
(ResponseContract.lean:18-86, 89-94)
- Rule is a constructor-for-constructor re-indexing of AuthTree, AuthField and AuthItems. Each
  rule asks for the same snapshot-computed evidence (projectOccurrence ... = some r, the
  taskOccurrences list) rather than node or row evidence. So rules_preserve is a renaming. That is
  legitimate, since AuthTree stays the independent target, but it adds no bridge content.
- OutputBridge render selection s p is ∀ op, Satisfies s p (selection op) (render op). That is
  AuthorizedResponse in rule form, stated about the final response. It does not break down into
  the per-constructor obligations that output reconstruction would discharge. Roadmap L456-457 has
  S3 define the bridge obligations and S4 discharge them, and the S4 text (L501-503) insists that
  "a generic framework theorem alone is not that bridge".
- A real representation gap stays implicit. Contracts and plans use record carriers, while Rule
  goals use occurrences (Context s). Building a rule derivation from rendered records means
  recovering the occurrence at each position: the exact Expected lists give
  projectOccurrences.map value, and so on. With duplicate equal records, only positional
  correspondence, not the record values, identifies the occurrence.
Fix (before S4 starts on output reconstruction): state the obligation at render granularity, on
top of B1's FrameInvariant.
  - Define RowFor request : carriers o → Context s → Prop as positional correspondence, the Nth
    record row against the Nth occurrence from Expected's occurrence-level lists.
  - State: render over any frame satisfying FrameInvariant, with frame rows related by RowFor,
    yields a tree with a Rule derivation for (.fields ctx selection path).
  - Prove it for the deterministic contracts in S3 if possible; it is pure.
  - S4 then has to show only that its interpreter produces such frames, including the declared
    framework-failure extension.
  - Keep the current OutputBridge as the corollary.

MEDIUM
M1. ResultSpec is not connected to the program. (ResultSpec.lean; BoundedExample.lean)
    - The tenant does not instantiate ResultSpec. Contracts.lean imports it and never uses it.
    - The output plan's render is never shown to preserve any ResultSpec.
    - In BoundedExample, plan_certificate, completed_bound and response_bound are three
      unconnected facts. completed_bound concerns a literal replicate list, not the plan's
      denotation, and ResponseRule is unrelated to the plan's output.
    The completion rules are therefore only exercised on literals. Compose them: the plan's call
    outcome, then the collect completion, then the response judgment, in one theorem. S4's
    items(first:) acceptance needs exactly that composition. Its fault-safety part is S4, but the
    pure composition can be shown now.
M2. The ownership mutation tests an output value, not a mutated implementation.
    removed_ownership_guard_rejected refutes `post` on one forged result. The acceptance text
    (L478-479) concerns removing the check from the resolver. Add a mutated backend, for example
    `project` searching by ID without the tenant test, as an adapter or Meanings, and prove
    ¬ BackendSatisfies Contract.tenant for it, using the Checks snapshot, where a foreign
    "shared" project precedes the owned one.
M3. The ContractRemovedGuard compile fixture fails on the exactness conjunct (rfl against
    Expected), not on ownership. That fixture would still fail if the ownership conjunct were
    deleted from `post`. The positive theorem does use ownership, so this is diagnostic only. Pin
    the fixture to the ownership conjunct. For example, assert AllowedOutcome for the forged
    value, or pin "OwnedProject" or "tenant" in the expected diagnostic.

LOW
