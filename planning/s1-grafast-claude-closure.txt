THE TASK.PROJECT REDIRECTION
This is sound, and it is an improvement. The earlier draft needed task-ID loads hidden inside an
opaque Project.tasks resolver, which only the future plan-resolver API could expose. Task.project
is an existing selected field-call node, so the rewrite stays within the declared interface. The
key-sufficiency theorem (L567-569) is the right extra obligation: rows differ but outcomes depend
only on (scope, projectId). It rests on the S3 row invariant that the rows are owned tasks, which
the new node/row contracts supply. Counting Project.tasks separately (L557-558) keeps the bound
honest.
Feasibility: the gather here spans two region levels (project rows, then task rows). It is the
composition of two one-level gathers. S1d already requires "nested parent positions" (L377), so
state the composition law there.

REMAINING CORRECTIONS (wording only; not S1 blockers)

C1. The chain's bound can be met vacuously. (L800-802 against L589-591)
countedMachineBatchCalls counts batch calls only. A strategy that falls back to single calls emits
none, so it satisfies ceil(U/B) trivially. L590 says "no additional single-lookup calls for that
transformed load", but the chain statement drops this, and L414's prose rule is not a theorem.
Correction: count every primitive call issued for that load, single and batch, as in
  countedPrimitiveCalls (load regionWave) <= ceil(U / B)
or state both conjuncts. Make the theorem conditional on the batch capability being present, so
the fallback case is plainly outside it.

C2. The deduplication key and its sufficiency law have no home in the interface.
(L410-413, L566-569, L794-795)
Deduplication needs a field-specific key function, such as Task to (scope, projectId). It also
needs the law that equal keys give equal outcomes for the backend actually used. The roadmap proves
that law for the pure backend only. The general equivalence theorem assumes only
DeterministicBatchRefinement, the pointwise batch-equals-single law, which does not justify sending
one representative per key. As written, the theorem is unprovable for a general deterministic
backend, or silently specialized to the pure one.
Correction:
 - Put an optional key function and its sufficiency obligation into the S2a batch-capability slot,
   next to the pointwise postcondition, so S2b preserves it.
 - Include key sufficiency in the eligibility predicate or in the refinement premise of the S4b
   theorem.
 - Make U in the bound (distinctScopedKeys) refer to that same key function.
 - Scope may be a request-context token rather than data. That keeps L344-347, which forbids
   capturing a principal's records in plans, consistent with Call.batch's scope argument (L250).
