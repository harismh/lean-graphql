OBSERVATION (not a finding, but say it plainly)
Generated.application is `fromCanonical Binding.independentBindings` (Generated.lean:123). So
the runtime bindings are the agreement target itself, and application_agreement is reflexive.
The substantive guarantees are elsewhere:
(1) adapter_agreement is universal over every BindingsByField family, which means the generated
    dispatch is the identity on canonical coordinates. The generator mutation tests exactly
    this.
(2) The domain meaning of independentBindings is proved independently, by S2a's
    binding_agrees_s1 and S3's tenantResolvers_satisfy_contracts.
That matches the roadmap ("Applications prove domain facts, while generation supplies
representation plumbing"). It differs from S2a, though: there, a hand-written ResolverRecord of
wrapper constants was checked against a separate target. The status should not suggest a
separate user implementation is still being checked against a separate target.

FINDINGS
M1 (Medium) Generated argument records and named accessors are not on the execution path.
   - FieldBinding.single receives `field.Args`, the encoded positional tuple.
   - Binding.independentBindings destructures it by position. For example, Bindings.lean:148
     reads `fun request parent key => ... ⟨key⟩`.
   - Args_i_j, its pack/unpack and arg_k_name (Generated.lean:33-81) are referenced only by
     their own theorems and the fixture examples. Neither the adapter nor any binding consumes
     them.
   Consequences:
   - The generator cannot swap arguments today, because it never touches them. That is safe,
     but it holds because nothing is generated there, not because of the records.
   - For a multi-argument field, nothing ties the user's positional destructuring to argument
     names. A user who writes `fun _ _ (right, left, _) => ...` gets no argument-identity
     diagnostic. Only that field's domain proof could catch it.
   - Every G2 fixture is standalone (pairArguments) or uses dummy bindings
     (GeneratorFixture). No executed field has two or more arguments.
   Fix: choose one of the following.
   (a) Make the binding boundary name-based. independentBindings (or a generated adapter
       wrapper) reads arguments through ArgumentRecord and NamedArgument, for example a
       FieldBinding single over ArgumentRecord, unpacked by the adapter, with a proved
       conversion law. Then add one executed multi-argument field and a swap fixture.
   (b) Narrow the status: the records are optional, name-checked helpers. Resolver argument
       identity remains the application's positional responsibility and is covered only by its
       domain proofs. Record (a) as an S5 obligation, since S5 coerces named arguments.
   (b) is enough for S2b closure, because the tenant has one argument.
L1 (Low) The mutation diagnostic is indirect.
   - mutation.log shows two "omega could not prove the goal" errors at Mutated.lean:121. They
     come from the fallback branch of `first | rfl | simp [ast] ... <;> omega`. The agreement
     goal that fails is never printed.
   - The harness accepts any error inside the adapter_agreement line range.
   The test is valid as a differential, since the original builds with the same script. But a
   future tactic change that breaks that range for another reason would be harder to tell
   apart. Fix: also emit, in mutation mode only, a positive theorem
   `¬ BindingAgreement independentBindings (adapter application)`, as S2a's
   swapped_wrapper_rejected did. Alternatively, make the out-of-range branch fail with a
   distinct message, and match the unsolved goal mentioning Project.id.
L2 (Low) The benchmark measures schema correspondence only.
   - The generated adapter_agreement (owners × maxFields case split with simp and omega
     fallbacks) and the three per-field argument theorems (2,400 at 800 fields) are not
     measured.
   - So "separate argument and binding proofs" (status) is not chosen on measured data, and
     only the monolithic-versus-per-object question is.
   - No scalability claim is made, so this does not block. Measure a generated 800-field
     artifact end to end before S8 or any larger schema.
L3 (Low) The generated and hand-written schema evidence are joined only by definitional
   unfolding.
   - Generated.indexed (match lambdas) and Binding.indexedSchema (Planning.schema.fields plus an
     `if` layout) are different terms.
   - Runtime.run (Generated.adapter …) and application_agreement typecheck only because the two
     closed terms reduce to each other.
   - A drift between them would show up as a confusing type mismatch in S2bProofs.
   Fix: add explicit pins, for example
   `Generated.indexed.schema = Binding.indexedSchema.schema := rfl` and an argumentLayouts
   equality, so the failure is local and named.
L4 (Low) adapter_agreement covers only records of the form fromCanonical b.
   - A Resolvers value built directly by its named fields is outside every theorem.
   - Today nothing does that, and fromCanonical is the only entry. State in the status, or in a
     generated comment, that BindingsByField is the only supported input and Resolvers is
     internal. Otherwise, a future user filling the named record could assume coverage that
     does not exist.
L5 (Low) Encoding facts are checked per artifact.
   - There is no general lemma that WellFormedSchema implies
     argumentsEncoding args = some (argumentCode args).
   - The emitted `Args_i_j.pack (value : (checked.field …).Args)` typechecks by per-artifact
     reduction of indexed.fields against argumentCode. argumentKind's `.unit` fallback is sound
     only because of WellFormedSchema.
   - A general lemma would make the argument-record API usable without kernel unfolding.
   Cosmetic: the generated file triggers an unused-simp-argument warning at
   Generated.lean:109 (`simp [ast]`).
